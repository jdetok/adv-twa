# Team Working Agreement (Draft)
### Analytics & Data Visualization (ADV)

## Core Team Values
- ### Commitment/Professionalism
	- We all show up **on time** to every team meeting/event.
	- We treat this course as if it were a professional internship. 
- ### Respect
	- We demonstrate a mutual level of respect toward each and every team member.
		- We actively listen to our teammates without interrupting.
		- We provide constructive criticism when beneficial - we avoid ***any*** demeaning or belittling language toward one another. 
- ### Transparency 
	- We regularly share work-in-progress, speak openly through blockers/issues, and communicate freely through decisions.
	- Clarifying questions are encouraged - we ask questions early and often!
- ### Humility/Team Buy-In
	- We understand that no individual is more important/valuable to the group than any other individual. We are one team, and all the work we do individually will contribute meaningfully to the project(s).

## Collaborative Work Approach
- ### Working between projects
	- Our team will **not** assign static sub-teams to work specific projects
	- The work required for any given project will vary greatly from sprint to sprint - developers are expected to have familiarity in each codebase and pick up issues in different projects over the course of the semester.
- ### Picking up issues/development workflow
	- On the first Monday of a new sprint at least ***six*** issues will be posted across the three projects and marked with a milestone named after the sprint that is beginning.
		- The tech lead will send a message in the #team_analytics channel when these issues are ready to be picked up by developers. 
		- Developers are expected to comment on the issue *and* send a message in slack indicating that they would like to work it. 
- ### Code Submission/Review Expectations
	- Developers are not ***required*** to submit their pull requests until class on Mondays
		- However, to allow adequate time for review, developers are *expected* to submit their PRs by **5pm on Sundays**
## Meeting Schedule/Availability
- Tech lead and developers must be present for all in-person class meetings. (Mondays 4:10pm-5:50pm)
- If a team member is unable to attend a meeting, they should notify the team's slack channel as early as possible. 
## Communication Standards
- The team slack channel #team_analytics should be used for all project/team communication
- All team members (including tech lead) are expected to **respond to messages on Slack within 24 hours**, unless during university breaks or other extenuating circumstances. 
## Artifacts, Tools, Definition of Done (DoD)
- ### Single source of truth
	- The main branch of each project's Github repository acts as the projects single source of truth.
	- All project documentation ***must*** live here. 
- ### Definition of Done (DoD)
	- Each team member shares the same definition of done; code has been reviewed, all tests are passing, and PR approved by tech lead. 

## Decision-Making & Conflict Resolution
- ### How we make decisions
	- Our team employs a relatively laissez-faire decision making framework:
		- Decisions will be discussed openly in class or in the #team_analytics slack channel.
		- Every member of the team is encouraged to give input on any given decision.
		- We do not formally vote on decisions
			- Rather, a consensus must be reached among those actively participating in the discussion. Once a consensus has been reached, the tech lead will send a message with confirmation of this consensus. 
			- If a consensus can not be reached, the issue will be discussed in the next sprint retrospective. 
- ### Disagreements/Conflicts
	- If a disagreement/conflict arises between individuals:
		- First, each party should exhaust all options for resolving the conflict between themselves.
		- If this is not possible, the tech lead or professor should be notified.
